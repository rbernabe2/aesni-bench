### Mask finding (affects the proposal text)

The proposal's mask, `OPENSSL_ia32cap=~0x200000200000000`, does not do what we
described on this machine with OpenSSL 3.6.5:

1. When a capability word is left out of the variable, OpenSSL sets it to zero.
   The original string therefore also turned off AVX2/AVX-512/VAES/SHA etc.,
   and the ChaCha20 control dropped 2.3× (`openssl_speed_20261029_171601`).
2. Hiding only AES-NI + PCLMULQDQ (`~0x200000200000000:~0x0:~0x0`) left
   AES-GCM unchanged, 6,006 vs 6,002 MB/s at 16 KB (`openssl_speed_20261029_172035`).
   On Zen 4, OpenSSL's fastest GCM code uses **VAES + VPCLMULQDQ** (AVX-512
   versions), which it checks in the second word.
3. The mask we now use, `~0x200000200000000:~0x60000000000:~0x0`, clears exactly
   AES-NI, PCLMULQDQ, VAES and VPCLMULQDQ and nothing else. This is verified
   by OpenSSL's CPUINFO line.

Diagnostic (`openssl_speed_20261029_172506`, AES-256-GCM, 16 KB): no mask
5,977 MB/s; VAES + VPCLMULQDQ hidden (classic AES-NI only) 2,535 MB/s; all
hardware AES hidden 175 MB/s.
